## Feature 1: Scanner/Database Split

### Current Architecture (v2.2)

**Single Addon: AscensionVanity**
```
AscensionVanity/
├── Core functionality (tooltips, progress, guides)
├── APIScanner.lua (data collection)
├── ScannerUI.lua (scanner interface)
└── VanityDB.lua (2,129 items, 667 KB)
```

**Problems:**
- Scanner tightly coupled with core addon
- VanityDB grows with every content update
- Scanner only needed for developers/contributors
- Most users never scan, only consume data

### Proposed Architecture (v2.3+)

**Split into TWO addons:**

#### 1. Ascension Vanity Stable Master (AVSM) - Core Addon
**What 95% of users need**

```
AscensionVanityStableMaster/
├── Core.lua                   # Tooltip enhancement
├── CollectionProgressFrame.lua # Progress tracker
├── RegionalGuide.lua          # Hunting guide
├── SettingsUI.lua             # Configuration
├── VanityDB.lua               # Database (read-only)
└── AscensionVanityStableMaster.toc
```

**Features:**
- ✅ Tooltips showing item drops
- ✅ Collection progress tracking
- ✅ Regional hunting guides
- ✅ Category filtering
- ✅ Quest-locked NPC warnings
- ❌ NO scanning (reduced complexity)

**Size:** ~800 KB (database + code)

#### 2. Ascension Vanity Database (AVDB) - Scanner Addon
**What developers/contributors need**

```
AscensionVanityDatabase/
├── APIScanner.lua             # Data extraction
├── ScannerUI.lua              # Scanner interface
├── ZoneExtractor.lua          # Zone data (future)
├── ExportTools.lua            # Data export utilities
└── AscensionVanityDatabase.toc
```

**Features:**
- ✅ Full API scanning (9,600+ items)
- ✅ Data export to JSON
- ✅ Quality filtering (Artifact/Legendary)
- ✅ Version tracking (game + build)
- ✅ Zone extraction (future)
- ✅ Metadata collection

**Size:** ~50 KB (no database, just tools)

**Workflow:**
1. Developers install AVDB addon
2. Run `/avdb scan` to extract latest data
3. Export to JSON via `/avdb export`
4. Process with PowerShell utilities
5. Generate VanityDB.lua for AVSM
6. Distribute AVSM to end users

### Benefits of Split

| Aspect | Current (v2.2) | Split (v2.3+) |
|--------|---------------|---------------|
| **End User Install** | 1 addon, ~900 KB | 1 addon, ~800 KB |
| **Developer Install** | Same addon | 2 addons, ~850 KB total |
| **Code Complexity** | Mixed concerns | Separation of concerns |
| **Update Frequency** | Same for all features | Core stable, scanner evolves |
| **User Confusion** | Scanner UI visible | Clean UI, no scanner clutter |
| **Maintenance** | One codebase | Two focused codebases |

### Migration Strategy

**v2.2 (Current):**
- Keep unified addon for stability
- No breaking changes for users

**v2.3 (Split):**
- Release both AVSM and AVDB
- AVSM replaces AscensionVanity (rename)
- AVDB is new developer-only addon
- Migration guide for existing users
- Backward compatibility for saved variables

**Compatibility:**
```lua
-- AVSM detects old AscensionVanityDB and migrates
if AscensionVanityDB then
    AscensionVanityStableMasterDB = AscensionVanityDB
    AscensionVanityDB = nil  -- Clean up old
end
```

### Questions to Resolve

1. **Naming:**
   - "Ascension Vanity Stable Master" vs "Ascension Stable Master"?
   - Does "Stable Master" communicate the purpose clearly?
   - Should we keep "Vanity" in the name?

2. **Database Updates:**
   - How do users get VanityDB updates without AVDB?
   - Option A: Include in AVSM releases (manual)
   - Option B: In-game update system (complex)
   - Option C: GitHub releases with VanityDB.lua (download)

3. **Feature Distribution:**
   - Should AVSM have `/avanity export` for sharing collection data?
   - Should AVDB have basic tooltips for testing?
   - Where does quest-locked NPC editing live?

4. **Branding:**
   - New logo for AVSM?
   - Keep "AscensionVanity" brand or rebrand entirely?
   - CurseForge/GitHub project names?

- Filter by: Collected, Not Collected, Category

- No "show on map" option
